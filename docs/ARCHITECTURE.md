# HTTPatch architecture

HTTPatch is a Manifest V3 extension. TypeScript and Preact build through Vite into
`dist/` for Chromium and `dist-firefox/` for Firefox.

## Data and rule application

`src/core/types.ts` defines the versioned storage and JSON export schema. Storage is
normalised by `src/core/storage.ts`; import validators are shared with file imports.
Original storage keys remain stable, scoped to HTTPatch's extension identity.

The pure compiler converts enabled profiles into `modifyHeaders` rules. Global
profiles use persistent dynamic rules; tab-only profiles use session rules with
`tabIds`. The tab-only flag is part of a synced profile, while the assigned tab ID
lives in device-local `storage.session` and disappears after a browser restart.
An unassigned tab-only profile emits no rule, preventing a synced or restarted
profile from silently becoming global.
Later profiles get higher priorities. Include filters fan out into alternatives,
resource types narrow the target, and supported domain excludes attach to each
condition. Profiles with only blank includes emit no rules; no includes means all URLs.

The apply adapter reconciles rules through `declarativeNetRequest`, checks browser
limits and returns status to the UI. Background scripts own this process. UI writes
persist first and then request an apply, debounced while typing.

## Browser sync

`sync.ts` contains pure reconciliation logic. `sync-runner.ts` orchestrates browser
storage reads and writes. One sync entry per profile respects per-item quotas;
tombstones retain deletions long enough for other devices to converge. Worker alarms
batch changes and periodically pick up remote edits. Sync failure does not prevent
local header rules from working. Sync is enabled by default and includes header values.

## User interface

The popup and options page use the shared store hook, components, profile factory
and theme. `src/ui/ProjectFooter.tsx` reads personal links from `src/brand.json`.
External links open only on a click, without sending profile data.

There are no content scripts. Domain validation is used by the compiler's exclude filters.

## Firefox and packaging

Firefox has its own manifest and event-page background. Build aliases replace browser
API adapters while retaining the shared compiler, sync engine and UI.
The Gecko ID is `httpatch@lukeosland1`. Minimum Firefox version remains 128.

`scripts/extension-assets.ts` includes the offline privacy page and licence in both
builds. Icons are generated by `scripts/gen-icons.mjs`. Packaging produces Chromium
ZIPs, optional signed CRXs and Firefox XPIs. Releases start as drafts; store uploads
are manually dispatched. The privacy page deploys from `main` when its source changes.
